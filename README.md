## Cluster & MPI Guardrails

When launching on a Slurm cluster, it's crucial to match the launcher's PMI version with the MPI library's expected PMI protocol. 
Flux.jl DDP is tested exclusively with Julia's default `MPICH_jll`, which uses the **PMI2** wire protocol.
If you use a system MPI (`JULIA_MPI_BINARY=system`), you must match your `srun` configuration accordingly. 

**Precompilation guardrail (Julia 1.12, measured 2026-09-03):** precompilation runs only on compute nodes. Login-node compiles target the wrong CPU (`graniterapids` vs `icelake-server`) and leave tests cold anyway. After every `sync_code.sh` or Flux source change, run `scripts/remote/precompile.sh bocconi` (precompiles thesis env + Flux test env under `srun`). `make env` no longer precompiles and `JULIA_PKG_PRECOMPILE_AUTO=0` keeps the login node compile-free during Pkg operations; a stale cache will still recompile silently at first load, so never skip the precompile step after a sync. Details and measurements: `wiki/context/remote-nodes.md`, `wiki/devlog/01-pr2694/2026-09-03-precompile-experiment.md`, ADR-0005.

**Guardrails implemented:**
- **Initialization checks**: `DistributedUtils.initialize(MPIBackend)` inspects `ENV` through `DistributedUtils.check_launcher_compat`. It throws only for the known-unsafe case `MPI.MPI_LIBRARY == "MPICH"` with `PMIX_RANK` or `OMPI_COMM_WORLD_RANK` present, unless `force=true` or MPI is already initialized; other environments are not judged.
- **Health Check**: Run `make health-check` to isolate MPI/PMI mismatches before attempting to train. This script prints the MPI version, PMI environment variables, and verifies process synchronization.
- **Launch Defaults**: Our `make` targets (`make launch-2`, `make launch-4`, `make health-check`) and remote scripts default to `srun --mpi=pmi2` within Slurm allocations via the `SLURM_MPI_TYPE` environment variable.
