# Devlog 2026-07-09: C2 Distributed Launch Skeleton

## Goal

Create a distributed launch skeleton (2-process and 4-process MPI launches) that completes without deadlock, both locally and remotely on the HPC.

## Actions

1. **Skeleton Script (`scripts/launch_skeleton.jl`)**
   - Created a basic script that initializes `DistributedUtils.MPIBackend`, retrieves `local_rank` and `total_workers`.
   - Included a dummy array broadcast (`DistributedUtils.bcast!`) from rank 0 to all other ranks.
   - Added an explicit `MPI.Barrier()` at the end of the script to prevent ranks from exiting early and causing deadlocks or hanging processes.

2. **Makefile Updates**
   - Added targets `launch-2` and `launch-4` that launch the skeleton script.
   - Using conditional logic to check for the presence of Slurm variables (`$SLURM_JOB_ID`):
     - If in a Slurm job, it uses `srun --mpi=pmi2 -n X julia ...`.
     - Otherwise, it falls back to `mpiexecjl -n X julia ...` for local launches.

3. **HPC Integration Challenges & Resolution**
   - We experienced repeated errors and precompilation floods on the HPC when `mpiexecjl` interacted with Slurm environments. Slurm sets `PMI_*` environment variables, and `mpiexecjl` crashes or hangs when the Slurm environment allocation configuration conflicts with MPI's internal PMI expectations.
   - We initially tried `srun --mpi=pmix`, which resulted in `Runtime environment uses unsupported PMI version PMIx. Aborting.` because Julia's precompiled `MPICH_jll` on Linux uses `pmi2` by default.
   - Changing `srun` to use `--mpi=pmi2` inside the `Makefile` solved the initialization crash.
   - We updated `scripts/run_remote.sh` to use `salloc --ntasks=4 --gres=gpu:0 --mem=32G --cpus-per-task=2 --account=3320522 --partition=stud --qos=stud`. This correctly provisions the resources via Slurm interactively. The inner `make launch-4` command (executing on the login node with the SLURM context) then safely dispatches the 4 tasks via `srun --mpi=pmi2` to the compute node. Note: `cpus-per-task` had to be reduced to 2 to stay within the QOSMaxCpuPerUserLimit of 8 for `--ntasks=4`.

## Results

- `make launch-2` and `make launch-4` pass successfully locally using `mpiexecjl`.
- `./scripts/run_remote.sh hpc make launch-4` runs flawlessly on the HPC `stud` partition using `srun --mpi=pmi2`. Output confirms 4 MPI processes communicate (broadcast) and barrier sync successfully.
