# 2026-07-28: C7 - Validation and Fixes

## Summary

Completed and validated Phase C7 of our DDP implementation. Addressed three critical blindspots in the end-to-end example and successfully validated execution on the HPC node using GPUs.

## Details

### Blindspot 1: Data Sharding Semantics
- **Issue:** The global dataset was being generated with a rank-dependent random seed (`Random.seed!(42 + rank)`).
- **Fix:** Replaced with `Random.seed!(42)` to ensure identical global dataset generation across all ranks before passing it to `DistributedDataContainer`. This guarantees correct sharding semantics where the global dataset is partitioned correctly.

### Blindspot 2: Missing Checkpointing
- **Issue:** The example lacked a demonstration of how to save the trained model.
- **Fix:** Added checkpointing logic using `JLD2.jldsave`. Crucially, this operation is restricted to `if rank == 0` to prevent concurrent write issues and unnecessary I/O overhead from multiple processes saving the identical state.

### Blindspot 3: Validation Loop Omission
- **Issue:** Training loop did not evaluate the model holistically across all ranks.
- **Fix:** Implemented a full validation loop calculating and logging the `Global Val Loss`. This uses `allreduce!` to aggregate the validation loss properly across all participating distributed ranks.

### HPC GPU Validation
- Successfully ran `make example-ddp` on the HPC node.
- **Backend Setup:** Utilized `NCCLBackend` communicating across 2 GPUs.
- **Dependency Fix:** Resolved an artifact download issue for `NCCL_jll` on CUDA 13.0, ensuring smooth initialization and execution on the cluster.
