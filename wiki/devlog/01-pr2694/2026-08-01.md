# Devlog: 2026-08-01 (C8.3 NCCL Verification)

## Context

C8.3 implementation was complete locally (MPI, 2/4 ranks, 78/78 tests). The NCCL verification on Bocconi was blocked — previous attempts failed because `salloc bash -c` runs on the login node without GPU access. The fix was using `mpiexecjl` inside salloc to launch processes on the GPU compute node.

## Bocconi GPU Access Pattern

**Wrong** (salloc bash runs on login node, no CUDA):
```bash
salloc --gres=gpu:2 bash -c "julia -e 'using CUDA; ...'"
# Runs on slnode01, libcuda.so.1 not found
```

**Correct** (mpiexecjl launches on GPU compute node):
```bash
salloc --gres=gpu:2 bash -c "mpiexecjl -n 2 julia -e 'using CUDA; ...'"
# Runs on gnode01, 4x NVIDIA A100 80GB visible
```

The `scripts/remote/run.sh` wrapper was also problematic — its `bash -l` invocation resets environment variables needed for CUDA. Direct `ssh bocconi 'salloc ...'` is required.

## Fix: `check_cross_rank_sync` NCCL Compatibility

**Root cause:** `check_cross_rank_sync` in `helper.jl:60` used `comm = backend.comm` which for `NCCLBackend` returns an `NCCL.Communicator`. `MPI.Bcast!` only accepts `MPI.Comm`, causing `MethodError`.

**Fix:** Replaced `MPI.Bcast!(ref, 0, comm)` with `DistributedUtils.bcast!(backend, ref; root=0)`, which dispatches to `NCCL.Broadcast!` for CuArrays on NCCL backend or `MPI.Bcast!` for CPU arrays on MPIBackend.

**File changed:** `ddp_flux/test/ext_distributed/helper.jl:58-86`
