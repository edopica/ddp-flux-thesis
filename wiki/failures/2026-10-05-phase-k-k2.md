# Phase K K2 readiness: SSH selected system Julia

Date: 2026-10-05. Host: deathstar. Scope: readiness only.

## Failure

The first environment probe used this command with Julia source on standard input:

```bash
ssh -o BatchMode=yes deathstar 'env JULIA_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 JULIA_PKG_PRECOMPILE_AUTO=0 timeout --signal=TERM --kill-after=10s 180s julia --startup-file=no --project=/home/picazio/projects/flux-integration/test -'
```

The command failed before package loading. Julia reported:

```text
ERROR: SystemError: opening file "/home/picazio/-": No such file or directory
```

The tool did not print the numeric exit status for this first command. The failed command produced no training result.

## Cause and correction

A non-login SSH shell resolves `julia` to `/usr/bin/julia`, version 1.6.2.
That binary treats `-` as a filename in this invocation.
The login shell resolves Juliaup, version 1.12.6, at `/home/picazio/.juliaup/bin/julia`.

These diagnostic commands succeeded:

```bash
ssh -o BatchMode=yes deathstar 'bash -l -c "command -v julia && julia --version"'
ssh -o BatchMode=yes deathstar '/usr/bin/julia --version'
```

The corrected probe uses the absolute Juliaup path and `include_string` for standard input.
It loaded Flux from `/home/picazio/projects/flux-integration/src/Flux.jl` and printed `READINESS_ONLY_OK`.
CUDA and cuDNN were functional. All three GPUs were visible.

The reproducible probe is `temp/phase_k_k2_readiness.jl`.
The baseline records its exact command and explicit exit status.

## Next action

Use the absolute Juliaup path for direct SSH commands.
Use `scripts/remote/run.sh deathstar` for later campaign commands with its login-shell environment.

The complete SSH command and input file appear in `temp/phase_k_k2_baseline.md` under the environment evidence.

The correction used Bash `time` with `TIMEFORMAT` and explicit status capture.
